## 2026-08-21 (3)

- **SPA-114 — The platform stops discarding most of what a reasoning model produces, and then grading it on the remainder.** A reasoning model returns its deliberation in a field separate from the answer, and `grep -rn "reasoning_content" agent-image/ backend/app/` returned zero. Measured live on MiniMax-M3 while building this: on a one-word reply, **44 of 48 output tokens were reasoning** — thrown away, and billed. The process judge was then asked how the agent worked across `efficiency`, `tool_selection`, `error_recovery` and `goal_alignment`, every one of which, on such a model, is answered largely in the stream nobody kept. Same shape as SPA-86 (arguments were never recorded, so `parameter_quality` had no subject) and SPA-113 (the trace was not in the order things happened): the recording layer was at fault and the model was charged for it.
  - **Captured once, whatever the vendor calls it.** `reasoning_content` (MiniMax, DeepSeek and most OpenAI-compatible servers), `reasoning` (OpenAI), `provider_specific_fields`, Anthropic `thinking` blocks, and the inline `<think>…</think>` some endpoints emit straight into the text — all normalize to one field, because a per-vendor column makes every consumer learn the vendor list. The inline case is *lifted out* of the text rather than copied: otherwise the answer keeps a blob the model never meant as its answer, and the outcome judge grades it.
  - **Stored apart from what the model said.** New `agent_log_chunks.reasoning`, never merged into `content` — mixing them would silently change what every existing consumer reads, and «the model's private deliberation» vs «what it did» is exactly the distinction worth keeping. It rides on the first tool call of a turn, since the thought preceded the turn and not each call within it; the final turn, having no call to carry it, sends a carrier chunk with no tool and no output, which the cleaner surfaces as reasoning and **not** as a nameless empty tool step — the loop counter would otherwise score an action the agent never took. The MinIO archive carries the field too, because a field the live trace has and the archived one silently lacks is the bug SPA-113 just finished fixing.
  - **First in the sacrifice order, reversing SPA-86.** Its own step kind (`model_reasoning`) with its own cap, given up **before** tool outputs. SPA-86 protected reasoning relative to outputs, but that ordering was chosen when «reasoning» meant the orchestrator's one-line rationale, not a model's full thinking — inherited unchanged, one talkative turn would evict the calls it is supposed to explain. A tool call plus its result is denser evidence per token about how the agent *worked*, which is the question being asked.
  - **Whether the judge sees it is a recorded condition, not a detail.** `eval_config.trajectory_show_reasoning`, default **true**, stamped into the write-once eval_config the revision fingerprint covers; the profile carries `reasoning_shown` and `n_reasoning_steps` (**trajectory schema 4→5**), the same shape as `files_only` on the outcome judge. Shown by default because `error_recovery` and `goal_alignment` are questions about intent that the judge currently infers from tool calls and a final answer. The argument against is real — private reasoning is not behaviour, and grading it rewards models that narrate well — which is why it is a switch. Withholding hides the steps from the JUDGE only; the trace keeps them, so the same run can be re-judged the other way without re-running the agent. `n_reasoning_steps` counts what the RUN had, so «withheld» and «the model never reasoned» stay distinct. **Consequence to carry into the next corpus:** an E-07 score computed over a richer input does not inherit prior κ against humans.
  - **Thinking and writing stop being one number.** Reasoning tokens are a SUBSET of `completion_tokens` and are billed, so SPA-77's token-effort metric was already charging for work no evaluator ever saw — a reasoning model looked expensive and shallow at the same time, both halves artefacts. New `quality_records.reasoning_tokens` (NULL, not 0, when the model does not reason or the provider does not say) and a **Thinking** column in the report: the share of OUTPUT tokens spent deliberating, not of the total, since dividing by input+output would understate it by however long the prompt happened to be. **`SCHEMA_VERSION` 19→20.**
  - **UI.** The agent log viewer renders a step's deliberation above its output, in its own muted style. Two new Cheat Sheet entries.
  - **Verified live on MiniMax-M3, which found three defects the unit tests could not.** A real agent run's trace now carries the model's deliberation (179 chars on the first call, stored apart from the output and surviving compaction), `token_usage` reports `reasoning_tokens: 169`, and E-07 scores it with `reasoning_shown: true` / `n_reasoning_steps: 1`. Getting there took three fixes, each invisible to a unit test that did not cross the layer in question: (1) `TokenUsage` in the webhook schema is `extra: "ignore"`, so an undeclared `reasoning_tokens` was dropped silently between the wire and the database — the first run reported 103 reasoning tokens in its webhook and stored a task with none; (2) the archive→chunk reconstruction in the trace cleaner did not carry the field, so a *compacted* run lost what a live one showed — the encoder and decoder alone were not enough, which is SPA-113's asymmetry one layer further in; (3) a regression this change surfaced in SPA-111, below.
  - **Coverage.** 13 new tests across the cleaner, the archive round-trip and reconstruction, the trim order, the judge switch, the wire schema and the effort split; a migration that round-trips.

## 2026-08-21 (2)

- **SPA-111 — The platform stops under-reporting what it spends, and stops charging a run for its provider's refusal to answer.** Two defects in how the backend talks to LLM backends, found while mapping the inference layer.
  - **The orchestrator's own calls were never costed.** `select_template_for_task`, `decide_decomposition` and `evaluate_agent_result` each make an LLM call and none of them read `response.usage` — judges were costed, agents were costed, the orchestrator was not. Every cost figure the platform reported was therefore an undercount by an unknown margin, and the experiment budget cap only counted part of what was actually being spent, which is the half that costs money. Usage is now read at all three sites and attributed to the task, priced from the live model row the way judge cost already is. It is stored **apart** from `cost_usd` / `token_usage`: those are the agent's own effort and feed the token-effort comparison (SPA-77), so folding orchestration overhead into them would make an orchestrated run look like a wordier agent and quietly corrupt the axis every model comparison rests on. `orchestrator_usage` accumulates across decomposition, selection, evaluation and any re-queue's repeats, and records which decision spent what. The report's cost breakdown gains an **Orchestrator** column — a panel that existed in the JSON since SPA-73 and had never been rendered — with `orchestrator_metered` to distinguish a config that spent nothing on orchestration from a corpus recorded before the meter existed, since both show as a zero. **No backfill:** the tokens those calls burned were never recorded anywhere, so historical rows keep an honest zero rather than an invented figure.
  - **Exactly one of twelve forced-tool-call sites survived a provider that ignores `tool_choice`.** Every judge and orchestrator call forces a tool by name and then reads `tool_calls[0].function.arguments`; E-07 alone fell back to parsing JSON out of `message.content`, a private robustness fix that was the reason ~27% of its evals stopped erroring. On any other site a provider that treats forced tool choice as advisory — plenty of OpenAI-compatible servers do — broke the orchestrator outright (it could not select a template, so it silently substituted the first one and pinned it) and failed E-02's critical dimensions **closed**, which the gate then reported as a *quality* failure. That reader is now the shared `app/utils/tool_args.py` used by all twelve sites. The one call deliberately left alone is `decide_decomposition`, the sole orchestrator call made with `tool_choice="auto"`, where the absence of a tool call is a legitimate answer («execute directly») and a content fallback would turn a decision into a parse error.
  - **An infrastructure failure is no longer scored as a bad deliverable.** When neither a tool call nor a parseable object comes back, the reader raises `ProviderComplianceError` rather than a bare parse error. `classify_llm_error` types it as `infra` — contaminating, by the same bar as a dead key: it is a property of the endpoint, identical on every task, and never a thing the run did — so an orchestrator that degraded because of it marks the condition instead of passing the substitution off as its own decision. A malformed tool call that IS present stays an ordinary parse error, because that one is the model's output and retrying it can help; conflating the two would let a bad-output retry masquerade as an infrastructure fault. Evaluator error dicts carry `error_class`, the E-02 profile carries `gate.uncertifiable_dimensions` (**profile schema 3→4**), and the report counts those runs separately per config. **The verdict is unchanged** — SPA-51's fail-closed rule stands, because we still cannot certify a critical requirement we never measured — but a config whose gate pass rate is depressed this way is being under-measured, not out-performed, and the two now read differently. **`SCHEMA_VERSION` 18→19.**
  - **An empty tool call is the same failure as no tool call.** Caught while verifying SPA-114 live: E-07's private reader had always fallen through to `content` when a tool call was *present but its arguments were blank*, and lifting the reader into the shared layer dropped that. Reasoning models do this routinely — MiniMax-M3 as an E-07 judge returns a named tool call with empty arguments and the JSON in `content` — so the shared reader broke the very site it was lifted from, and every judge on the stand with it. Restored, and pinned by a test: the provider announced the call and put the answer somewhere else, which is not a different failure from never announcing it. A tool call carrying *malformed* arguments still stays an ordinary parse error — that one is the model's output.
  - **Post-review: the classification has to survive the profile.** `error_class` was computed inside each evaluator and then dropped by five of the six profile assemblers, which rebuilt their `errors` list by hand as `[{"error": …}]`. E-02 carried it from the start; E-07, E-08, E-14, E-15 and E-16 arrived in the report as bare text — indistinguishable from a judge that broke on its own, which is the exact state this ticket set out to fix. All six now carry it, including the per-step evidence errors. Pinned twice: by running E-07 against a non-compliant provider, and by a source scan that asserts it found something to check, so it cannot pass vacuously.
  - **Coverage.** 23 new tests across the shared reader, orchestrator attribution, the gate and the report; a migration that round-trips. Verified live against MiniMax-M3: a real template-selection call attributed 664 in / 412 out to its task at $0.000694, exactly the arithmetic, with the agent's own `cost_usd` and `token_usage` untouched. Worth knowing about this stand: the MiniMax-M3 row the workspace actually uses carries 0.00/0.00 prices, so every cost it reports — agent, judge and now orchestrator alike — is a true $0 until that row is priced.

## 2026-08-21

- **SPA-115 — Five defects found reviewing SPA-62 and SPA-113, four of them breaking a guarantee the originating ticket had just claimed to establish.**
  - **A rank-only axis was back in the numeric aggregates.** `_compare_cells` correctly skipped Welch and the paired t-test for a rank-rescued metric — and then computed Cohen's d_z, a bootstrap CI on the **mean** difference, a power analysis and a TOST verdict for it anyway, all of which the UI rendered. Every one of those is a claim about size, which is the one thing a scale-shifted judge cannot support: a strictly monotone rescaling that preserves every rank moved the review's example from p = 0.0759 to p = 0.0346. Skipping the mean-based *test* was never enough. Such a row now carries `magnitudes_withheld: rank_only_axis` with all four fields null, and the table says **withheld — ranks only** rather than leaving a blank that reads as missing data. **And the verdict itself had the same problem one level down:** the paired rank-only primary was Wilcoxon, which despite the name ranks the *magnitudes of the differences* — a rescaling of the scores reorders them, moving p from 0.0206 to 0.0225 on a seven-case fixture and, with the right numbers, across 0.05. The primary is now the sign test, the only paired test that is genuinely invariant (`sign(f(a) − f(b)) = sign(a − b)` for any strictly increasing `f`); Wilcoxon is kept as a diagnostic. Mann-Whitney was already safe for the unpaired case, since it ranks the raw values. The property test that should have caught this used four pairs — below Wilcoxon's minimum — so the row fell through to the sign test and the property held for the wrong reason while the code was wrong; it now uses seven, and fails against the old code.
  - **The design no longer changes because an inference is unavailable.** When every within-case difference was identical, `paired_t_test` returned `None` and the row silently became `unpaired` and reported Welch's numbers. On four cases shifted by exactly +1 — the *strongest* paired evidence a matrix that size can produce — it reported p = 0.55, an unpaired CI of [−5.5, 3.5] and `n_required: 236`, against a paired bootstrap CI of [−1, −1]. Not a weaker answer: the opposite one. The design describes the experiment, not the arithmetic, so it stays `paired` and falls through to an **exact sign test**, which needs only the signs of the differences and therefore survives both degeneracies that stop the others. Four unanimous cases give p = 0.125 — the honest ceiling of a four-case design. Two configs that scored *identically* on every case defeat all three paired tests, and that is the most definite answer there is rather than the absence of one: the row survives as `primary_test: identical`, p = 1.0, with the exact equivalence verdict beside it.
  - **The loop counter stopped gluing attempts together.** SPA-113 folded the attempt index into the action identity, which fixed the run of identical actions — and nothing else, because `tool_seq` was still the concatenated trace and both the same-tool run and the tandem-cycle search read it. `search click search` followed by `click search click` is two ordinary attempts that concatenate into a `(search, click)` cycle three times over: `loop_detected: true` on a retry, which is the opposite of going in circles, on the very counter E-07 is anchored against. Sequence analysis is now per attempt with the maximum taken across them; a real loop inside one attempt is still caught, and a pre-SPA-113 archive with no attempt field behaves exactly as before.
  - **A contamination can no longer outlive the attempt it describes.** The re-queue guard read `template_id is not None` as «the orchestrator degraded and pinned a substitute» — but every orchestrated task has a template_id, including one that chose its template perfectly well and then died on an agent-side 429. That task kept `llm_rate_limit` through every re-queue, so its next, *successful* run was dropped from every aggregate by `measures_the_model()`, permanently and silently. Whose contamination it is has to be recorded rather than guessed: a new `tasks.condition_contaminated` is set only by the orchestrator degrade path, which is the only code that knows it substituted and pinned a template. No backfill — for rows written before the column, that provenance was never recorded, and defaulting them to false makes a re-queue clear the reason, which is the safe direction.
  - **A lost chunk can no longer erase a call from the trace.** The progress-echo rule matched on membership in a set of `(attempt, tool_name)`: with two same-named calls in one attempt of which one chunk never arrived, both pings matched the single recorded call and both were dropped — deleting the call the surviving ping was the last trace of, which is precisely the case the rule's exception was written for. Now counted, not merely present: at most as many pings go as there are calls actually recorded, per attempt.
  - **Coverage.** 10 new tests across statistics, the report, the loop counter, the cleaner and the task API, plus a migration that round-trips.

## 2026-08-19 (3)

- **SPA-62 — The report's statistics become claims a reviewer could check: paired by case, corrected for how many were asked, and honest about what «no difference» means.** The matrix has always run the *same cases* through every configuration, and the test has never known it. `significance_matrix` received a flat list of scores per config — case identity was destroyed at collection — so Welch compared two independent samples on a design that is paired, and every source of variation the two configs share stayed in the noise instead of cancelling. On a four-case matrix the spread between an easy case and a hard one dwarfs the spread between configs, which is exactly when an unpaired test goes blind to a consistent improvement.
  - **The comparison is paired by case, and the unit is the cell.** Scores are collected as `config → metric → case_key → value`, one value per (config, case) **cell**, averaged over that cell's repeated runs. Repeated runs of one case are not independent observations; entering them as such is pseudoreplication, and it inflates confidence precisely where the design is weakest. A consequence worth stating plainly: two cases run three times each used to look like six observations per config and is now correctly two — below three cases nothing is testable, and the report **says so** (`n_omitted`, `too_few_cases`) rather than showing an empty table that reads like «we looked and found nothing». Welch survives as the fallback for genuinely unpaired slices and as the cross-check on every paired row, so no number that was on screen has vanished.
  - **★ follows the corrected verdict, in two families.** A table of dozens of tests at α = 0.05 manufactures roughly one green row per twenty from nothing — Эксп 4b ran 42, Эксп 5b ran 48, and 5b's lone significant row (`dim:originality`, p = 0.0399, its own Mann-Whitney cross-check p = 0.093) is what that looks like. `significant` is now decided on a Benjamini-Hochberg q, and the uncorrected verdict is kept beside it (`was p<.05`) so a demotion is legible rather than a row that quietly stopped being green. Correction runs **within** a family, never across: `confirmatory` = the two headline metrics the experiment was built to compare, `exploratory` = the per-dimension screen over whatever the rubric happened to contain. Pooling them would make the screen's size the headline's problem. Each family prints its own test count.
  - **«Not significant» is no longer allowed to read as «no difference».** It means «we could not tell», and four cases cannot tell much. Every row that fails to reach significance now carries a TOST verdict against a margin fixed **before** the data — `eval_config.equivalence_margin`, stamped at create time into the frozen revision fingerprint exactly as `judge_threshold` is (SPA-87), default 0.5 judge points. The verdict is three-valued: **★ significant** / **≈ equivalent** (both one-sided tests reject a difference larger than the margin — a claim that could have been wrong) / **? inconclusive**, the last carrying what the design could have seen: the minimum detectable effect at 80% power, and the n the observed difference would have needed.
  - **Every row states its size, not only its verdict.** Mean difference with a 95% percentile-bootstrap interval that resamples **cases** (the unit the design repeats), plus a standardised effect — Cohen's d_z on paired rows, Hedges' g on unpaired ones, named on the row because they are standardised by different spreads and comparing them is meaningless.
  - **Intervals on the point estimates that decide things.** κ gains a bootstrap CI at all three sites (per-dimension, overall verdict, inter-annotator), resampling the judge–human **pairs**. This matters most where it is least comfortable: the SPA-88 reliability gate classifies an axis by the point estimate, and at the n an experiment produces the interval routinely reaches across both the 0.4 and the 0.6 cut-off. The interval is carried, **not acted on** — where those lines sit was decided in SPA-88 and re-deciding it here would be a different ticket wearing this one's branch. AUC gains a bootstrap CI; the 2×2 agreement, the over-credit cell, the checker pass rate and the success rate gain Wilson intervals — the textbook formula runs outside [0, 1] at these counts and reports `[0, 0]` on an empty over-credit cell, which is certainty asserted from no evidence.
  - **The population is named.** Scores exist only for runs that finished SUCCESS, so a configuration that fails more often is scored on its luckier subset; the same at case level — a case one config failed is absent from the pairing. `report.estimand` states the population, the unit and the quantity, and every row lists the cases only one side ran. Naming the estimand is this ticket; **changing** the population would be a different experiment, not a statistics fix.
  - **Acceptance, honestly.** The ticket asks that the audit's own findings be re-run through the new machinery. The corpus was wiped in SPA-113, so Эксп 5b no longer exists to re-run; the criterion is met by regression test instead — the audit's actual numbers (p = 0.0399 among 48 tests) come out **not significant**, and the paired-vs-Welch property is pinned by a fixture where Welch reports p > 0.5 on a shift the paired test finds at p < 0.01. On the surviving 5b fixture in the suite, the same row's verdict now rests on the paired test and is *strictly stronger* than the Welch number it replaced — which is the argument for pairing, visible on the audit's own case.
  - **UI.** The significance table gains Design (`paired n=4` / `unpaired`, with the cases only one side ran), Effect (difference + interval), separate p and q columns and the three-valued verdict; the header states how many tests ran per family and how many lost their star to the correction, with the estimand beneath it. κ shows its interval in the calibration table and in every axis tooltip; AUC and the 2×2 agreement show theirs. Nine new Cheat Sheet entries, written for someone who has never met a q-value. **`SCHEMA_VERSION` 17→18.**

## 2026-08-19 (2)

- **SPA-113 — The trace the process judge reads becomes a description of what happened.** Found on the first real agent run the stand has ever done: everything in SPA-84–88 had been verified against seeded data, unit fixtures, or the error branch of a dead provider key. SPA-86 fixed *what* is recorded per tool call; it did not touch order, attempt boundaries or duplication, so the judge was being scored against an input that misrepresented the run.
  - **Archived traces lost their clock, and with it their order.** `encode_log_archive` never wrote `created_at`, and the cleaner puts undated steps last — so the moment a task's logs were compacted, every tool call sorted after every event. On the live run that meant the judge read a trace where all six calls happened *after* the agent reported completion. The archive now carries the timestamp and the loader restores it. Archives written before this decode to `None` and keep the old order; there is nothing to migrate them from.
  - **A retry is no longer read as repetition.** Each `agent_spawned` opens an attempt; every step carries `attempt`, `stats.attempts` counts them, and a trace spanning more than one gets a visible boundary — rendered as a separator, never numbered, and never evicted by the budget trim, because dropping it turns a retry back into a loop. The loop counter folds the attempt into its action identity for the same reason: starting over is the opposite of going in circles.
  - **A progress ping stops counting as a second action.** `agent_progress` announces a call that the log chunk records in full, `recent_output` being a preview of the very result the chunk holds. Kept as its own step it doubled every call — and the judge counts actions: on this run E-07 scored `efficiency` **4/10** citing a file «written three separate times» that was written once. Two of the three did not exist. The ping is dropped only when the call it announces was actually recorded **in the same attempt**; when the chunk never arrived, the ping is the only surviving trace of that call and stays. **`TRACE_SCHEMA_VERSION` 2→3.**
  - **One decision logged twice is one step.** The orchestrator records a choice as both `orchestrator_reasoning` and `orchestrator_decision` with identical text; the judge read the pair as the agent acting twice and said so — «template_selected twice in steps 2-3» — docking efficiency. Adjacent, byte-identical, **non-tool** steps now collapse. Two identical tool calls never do: that is the repetition the structural counter exists to notice.
  - **A manual re-queue no longer inherits the failed attempt's reason.** `PATCH /api/tasks/{id}` with `status: ready` left `failure_type` in place, so a task that failed on infrastructure, was fixed, and was re-queued by hand carried `infra` into a **successful** run — which `measures_the_model()` then dropped from every aggregate, silently. The reason is cleared, with the SPA-87 exception intact: a contamination describing a condition **pinned** on the task (the degraded orchestrator chose a template and the next attempt will reuse it — the pin *is* `template_id`) survives, because that condition survives.
  - **`failure_type` becomes visible.** It was recorded correctly from the start and readable only in SQL: experiment surfaces carried it, the task itself did not. Now on the task API and badged in the UI, contaminating reasons distinguished from the run's own.
  - **Coverage.** 9 new tests: chronological interleaving, the echo rule and its exception, attempt boundaries and their absence on a single-attempt run, an archive round-trip preserving the clock, a retry not counting as a loop, a decision logged twice collapsing while two identical tool calls do not, and the three re-queue cases. Suite 970 → 979.
  - **Measured on the run that surfaced all of this**, re-judging the same trace after each fix: E-07 went 4/10 on `efficiency` citing a file «written three separate times» that was written once → 6.67 overall, still complaining about the duplicated decision → **7.17 overall**, with every remaining criticism corresponding to something the agent actually did («the apparent repetition is the system's two-attempt structure … not agent-stuck»). The point is not that the score rose; it is that the score became a statement about the agent.

## 2026-08-19

- **SPA-88 — The reliability gate stops being a badge and starts being a gate: raw vs trusted aggregates, and a rank-rescued axis barred from every mean.** SPA-76 graded each judged axis by its agreement with a human and SPA-79 rescued the rank-consistent ones, but nothing acted on either verdict. An axis marked `unreliable` still moved every mean, every Pareto point and every «significant» row — so `research_old/final_reports/competitor-comparison.md` claimed a quarantine the code did not perform.
  - **Two views, not one edited view.** The raw report keeps every axis, unchanged. A parallel `report.trusted` block recomputes the numbers a quarantined axis could have moved — Summary quality/trajectory, Pareto, the pairwise leaderboard, significance — from the axes that cleared the gate. Nothing is hidden, because excluding an axis is a claim about the **judge**, and the reader needs the unfiltered numbers to check it against. Success rate, cost, tokens and the executable checker are never gated: they are not the judge's opinion.
  - **Six statuses instead of four.** `directional` had been folding together three different situations that license three different claims. Now: `reliable_absolute` (κ ≥ 0.6) and `moderate_agreement` (0.4 ≤ κ < 0.6) may carry numeric aggregates; `rank_only` (κ below the bar but Spearman ρ ≥ 0.5 — the SPA-79 rescue) may carry **ordering and nothing else**; `insufficient` (too few pairs, or κ undefined), `unreliable` (κ < 0.4 and ρ < 0.5) and `not_calibrated` (no source) carry nothing. «Too little data to say» and «the judge disagrees» are different findings and no longer share a light.
  - **The critical rule: a rank-rescued axis never enters a numeric aggregate.** Averaging a scale-shifted judge is precisely the error the rescue exists to avoid — it orders runs correctly while its *level* means nothing, so its mean is a number without a referent. Hence two sets, not one flag: numeric-eligible axes drive every aggregate — the means, the Pareto frontier and the leaderboard, all three of which are built from magnitudes. The wider rank-eligible set buys exactly one thing, in the significance table: a rank-rescued axis keeps its own row, Welch is **not run at all** for it (Welch compares means), and the verdict rests on Mann-Whitney, marked `rank_only` — an approximate test and so a weaker claim, stated as one.
  - **A significance row now carries the axis it was measured through.** Both views tag every row with `axis: {kind, key, status, numeric, rank}`, because how far an axis is trusted is a condition of the claim the row makes, not a separate panel to join by hand. `trusted.dropped` says what the gate cost in the only currency that matters: how many «significant» rows vanished, which metrics they were, and how many survived but stopped being significant.
  - **Absent evidence is not adverse evidence.** With no calibration source at all — the ordinary state of a corpus annotated by one person — `trusted.available` is `false` and the UI says so, rather than presenting an empty table as a result. `not_calibrated` keeps an axis out of the trusted view as **unknown**, which the caption states separately from **quarantined**.
  - **UI.** A Raw / Trusted toggle above the report, with a caption naming what each state drops and why; `~ ranks` on a rank-only significance row with `n/a` where its Welch p would be; the heatmap legends rewritten to the new taxonomy; the Cheat Sheet entry rewritten. Verified live end to end on a seeded corpus whose three rubric axes land in three different buckets: the quarantined axis's `p = 0.000` row disappears, the rank-only axis survives on Mann-Whitney alone, and **the winner flips** — the configuration that led the raw leaderboard on the axis nobody can trust finishes second once the gate is applied.
  - **Two review findings, both about the word «only».** (1) The trusted leaderboard was fed by a weighted **mean** over the rank-eligible axes — so a rank-rescued axis was back in a numeric aggregate by the side door. The argument for it (`build_matches` compares two runs of the *same case*, which a scale shift survives) holds for one axis in isolation and fails the moment axes are combined: in a mean the axis contributes its magnitude, and rescaling it — precisely what «scale-shifted» licenses — flips the composite winner while changing no ordering the calibration ever validated. Spearman ρ constrains the order, not the size of a gap, and a mean is made of gaps. The leaderboard now runs on the numeric-trusted set like every other aggregate, and `rank_only` spends its licence in the one rank-pure place: its own Mann-Whitney row. Doing it properly — per-axis, per-case votes — would drop the rubric's weights and change what «better» means for the calibrated axes too, so it is a decision of its own rather than a detail of this one. A property test pins the invariant: rescaling a rank-only axis flips the raw winner and moves nothing in the trusted view. (2) The **calibration is an input the cache could not see.** A terminal report is cached and served while the schema, the revision and the input fingerprint still match — none of which move when a person rates a run. That was cosmetic while calibration drove a badge; now it decides which axes carry a number, so a report opened before annotation kept serving `trusted.available: false` and its pre-annotation winner until someone pressed Re-assemble. The report now records a `calibration_fingerprint` (the annotation population over its runs) and the cache is checked against it — fingerprinted rather than invalidated on write, for the same reason the input fingerprint is recomputed rather than read: a cache that measures its inputs cannot be defeated by a write path nobody remembered to hook. The fingerprint is sampled **before** the calibration it stamps: taken afterwards, an annotation committed in between lands in the fingerprint but not in the report, and that cache then looks valid permanently — taken first, the same race merely costs a recompute. - **SPA-86 — Trace capture: the process judge is finally shown the tool call, not just its name and its result.** `parameter_quality` is one of the six axes E-07 scores, and the parameters were never recorded anywhere: `agent.py` parsed `fn.arguments`, called the tool with them, logged 200 characters and threw them away — only the output and the tool's name were transmitted. `agent_log_chunks` had no column for them, so the data lake never had them to lose. ## 2026-08-11

- **SPA-112 — Live event relay: the Redis→WebSocket subscriber no longer dies on an idle channel.** Every API start logged `Redis subscriber crashed: Timeout reading from redis:6379` within seconds, after which no event reached any WebSocket client: the UI showed no live agent log and no live run progress until the page was reloaded and the frontend re-read from the DB.
  - **Cause.** redis-py 8.x defaults the connection's `socket_timeout` to 5s. `PubSub.listen()` reads with `block=True`, which falls back to that timeout, so any 5-second gap with no traffic raised `TimeoutError` — and idle gaps are the normal state of this channel. `_consume()` then caught the exception and *returned*, so nothing ever resubscribed. Because `_broadcast_event` publishes to Redis and returns early, the dead subscriber meant total silence rather than degraded delivery: events raised by any process, including the API's own, reached nobody.
  - **Fix** (`app/utils/events.py`): consume via `get_message(timeout=…)` (an idle poll returns `None` instead of raising, whatever the client default); wrap subscribe-and-consume in a reconnect loop with bounded backoff (1/2/5/10/30s); track `_subscriber_live` so that while the relay is down `_broadcast_event` also broadcasts locally, keeping a client's own events visible.
  - **Verified live**: 30s idle with no crash line; an event published from a separate process arriving at a connected WebSocket client; `docker compose restart redis` under a running API recovering via `resubscribing in 1s` with delivery working afterwards. Regression coverage in `tests/unit/test_event_subscriber.py` (5 tests over a scripted fake pubsub).
